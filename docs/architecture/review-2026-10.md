# Architecture review, October 2026

Snapshot: `main` at `3f90e716`. This is an analysis. No code changed. Each migration step in section 4 becomes its own task after approval.

How the numbers were taken: line counts are `wc -l` over `.ts`, `.tsx`, `.rs` and `.mjs` files, excluding `node_modules`, `dist` and `target`. Import counts come from a script that reads `import ... from`, `export ... from` and `import()` with relative specifiers under `apps/hub/src` (the hub uses no `@/` alias: 0 files). It separates value imports from `import type`. It is a text scan, not the TypeScript compiler, so treat counts as accurate to a few edges.

## Summary

The hub's three tiers (api, services, infra) mostly hold. The coordinator's inverted-dependency worry is mostly wrong: `infra/` has one back-edge, not many. The real structural costs are elsewhere:

1. `CLAUDE.md` is 163,186 bytes and every agent session loads it. 130,454 bytes (80%) are 25 "Architecture:" sections that belong in `docs/architecture/`.
2. 39 of the 78 flat service files form one import cycle, held together by `state.ts` (27 importers) and `worktree-service.ts` (23 importers).
3. The tier rules exist only as review criteria (`.claude/coding-criteria.md`, CODE-1 to CODE-19). Biome enforces only the `host-local` and `node:*` import rules. Both known tier violations got through.
4. `services/` is one flat folder of 78 files (30,618 lines) with no domain grouping, although clusters are visible by name (project: 8 files and 3,992 lines, context: 7 and 1,844).
5. The web app has two UI roots (`dashboard/`, 28,728 lines, and `components/`, 23,637 lines) that import each other, and one 4,660-line component.

## 2. Problems

Ranked by day-to-day cost.

### P1. `CLAUDE.md` is a 163 KB architecture book that every agent loads

- `CLAUDE.md`: 163,186 bytes, 493 lines, 30 `##` sections. Roughly 40k tokens at 4 bytes per token (an estimate, not measured).
- 25 sections are titled "Architecture: ...", totalling 130,454 bytes. The largest: projects 21,026, context repos and media 11,699, remote hosts 10,647, runners 9,483, tasks 9,228, MCP proxy 8,209.
- "Testing Strategy" adds 24,730 bytes, including about 20 per-file exceptions.
- `docs/architecture/` has one file (`hub-workers.md`, 83 lines). `docs/web-architecture.md` is 406 lines and `docs/tasks.md` is 59.

Cost: every session pays this context, including sessions that touch none of these areas. Single paragraphs are hundreds of words long, which makes line-by-line review and edits hard.

### P2. One 39-file import cycle in `services/`, behind two god modules

- Strongly connected component over value imports: 39 files, listed by name in the next sentence. They are `agent-launch`, `agent-session`, `agent-session-registry`, `branch-status-poller`, `chat`, `client-state`, `context` (7 files), `cronjob`, `ephemeral-lifecycle`, `git-credential`, `github-poll`, `github-webhook`, `mcp-proxy`, `mcp-stdio`, `placement`, `project` (7 files), `repo`, `runner`, `subscription`, `task`, `terminal`, `vault`, `watcher`, `worktree-script`, `worktree-service`, plus `_utils/git-token-source` and `_utils/hub-gh-auth`.
- Fan-in (files importing it, of which sibling services): `services/state.ts` 27 (20), `worktree-service.ts` 23 (20), `chat-service.ts` 23 (15), `watcher-service.ts` 18 (14), `project-service.ts` 16 (13), `task-service.ts` 15 (8).
- `state.ts` (544 lines) mixes unrelated jobs: `loadState`/`saveState`, `loadSettings`/`saveSettings`, token helpers and the whole worktree-status store (`upsertWorktreeStatus`, `applyHookNotification`, `startStatusSourceCleanup` and others). Ten files import only `loadState` from it.
- Large files: `agent-session-service.ts` 1,796, `worktree-service.ts` 1,569 (15 methods plus helpers), `runner-service.ts` 1,213, `diff-service.ts` 994.
- Only 45 of 78 service files declare a `constructor`, but 60 export a module-level `xService = new XService()`. CODE-10 asks for constructor injection with default arguments. The module singletons are what pull the cycle together at import time.

Cost: a change in `worktree-service` re-types and re-tests 23 files. No service can be loaded or understood alone, so an agent opening one file ends up reading six.

### P3. Tier rules are enforced by review only, and two violations exist

- `.claude/coding-criteria.md` states CODE-11 (a service never imports `api/**`) and CODE-17 (infra never imports `services/**` or `api/**`). `docs/web-architecture.md` says "Infra knows nothing about services."
- `biome.json` (236 lines) has `noRestrictedImports` overrides for `host-local` and `node:fs`, `node:child_process`, `node-pty`. It has no rule for the tiers. The `host-local` pattern block is repeated in three overrides (lines 76, 148, 195) plus an allowlist of about 20 files.
- Existing violations: `services/worker-relay-service.ts:20` imports `CHAT_ID_HEADER` and `WORKTREE_ID_HEADER` from `../api/context` (two string constants). `infra/host/registry.ts:113` does `await import("../../services/state")` to read `loadSettings().plugins.disabled`.
- `api/` reaches into `infra/` directly in 4 files (`api/chats/router.ts`, `api/project-tasks/router.ts` for `project-scope`; `api/hosts/router.ts`, `api/queue/router.ts` for `host/registry`). CODE-3 allows a router to forward to services only.

Cost: the rule is one a human reviewer has to remember. It fails open.

### P4. `services/` is flat

- 78 files and 30,618 lines in one folder, plus `_utils/` with 38 files. Name prefixes show the real domains: `project*` 8 files and 3,992 lines, `agent*` 3 and 2,111, `context*` 7 and 1,844, `runner*` 2 and 1,643, `worktree*` 2 and 1,803, `browser*` 4 and 773, `github*` 2 and 484.
- `_utils/` mixes domain code (`retro-prompt.ts`, `dispatch-brief.ts`, `task-backfill.ts`) with generic helpers (`fuzzy-score.ts`, `mime-types.ts`, `map-limited.ts`). Four `_utils` files import back into services (`git-token-source` and `hub-gh-auth` into `vault-service`, `shared-dir` and `upload-utils` into `state`).
- CODE-13 says stateful services that own processes or sockets belong in `infra/`. `services/` holds `watcher-service`, `terminal-service`, `branch-status-poller` and `file-watcher`, which do.

Cost: finding the owner of a feature takes a directory listing and a grep. There is no place where a domain's public surface is stated, so every sibling import is allowed.

### P5. Web app has two UI roots and a few very large files

- `apps/web/src/dashboard/` 114 files and 28,728 lines, `components/` 65 and 23,637, `lib/` 47 and 7,273, `hooks/` 15 and 2,198, `routes/` 4 and 1,171.
- `components/` imports from `dashboard/` in 33 files. `dashboard/` imports from `components/` in 2. So the older folder depends on the newer one, and neither can be moved alone.
- Largest files: `components/WorktreeCenterDockview.tsx` 4,660 lines (150 hook calls), `dashboard/components/FileBrowser.tsx` 1,883, `ProjectsDialog.tsx` 1,785, `lib/terminal-cache.ts` 1,619, `SettingsPage.tsx` 1,502, `ChatView.tsx` 1,488.

Cost: edits to the dockview component conflict across branches, and an agent needs 4,660 lines of context to change one tab behaviour.

### P6. Test setup cost

- `apps/hub` `pretest` runs `pnpm --filter @band-app/web build && pnpm build` before every `vitest run`. 171 hub test files and 146 web e2e specs run against that bundle. Root `pnpm test` chains 9 commands in sequence.
- A few suites call services directly (`git.test.ts`, `host-registry.test.ts`, `subscriptions.test.ts`), each recorded as an exception in `CLAUDE.md`. They exist because some behaviour has no public surface.

This follows from the integration-first policy, which the review keeps. It is listed because section 4 must not make it worse: a boundary change that needs mocks is out. This problem has no step of its own. I have no timing data, so I do not rank it higher.

### P7. Minor

- `src/api/` (4 files) beside `server/api/` conflicts with CODE-4's "one folder per domain under `server/api`".
- The singular and plural routers (`worktree/` and `worktrees/`, `chat/` and `chats/`) look like duplicates. They are separate tRPC namespaces with different keys, so they stay.
- `api/router.ts` carries a phase history of about 40 lines in its header comment.

## 3. Target structure

### Boundaries

Keep the package names and the tRPC and CLI surface. Change only the layout under `apps/hub/src/server`.

```
apps/hub/src/server/
  api/                      unchanged (one router folder per domain)
  services/
    projects/               project-*, task-*, dispatch, retro, coordinator
    context/                context-*
    agents/                 agent-*, chat-service, mcp-proxy, mcp-stdio
    worktrees/              worktree-service, worktree-script, watcher, branch-status
    runners/                runner-*, ephemeral-lifecycle, environment-*
    browser/                browser-*
    github/                 github-*, subscription, pushed-sha
    system/                 settings, state (shrunk), token, vault, tunnel, cli
    shared/                 the generic part of _utils
    <domain>/index.ts       the public surface of the domain
  infra/                    unchanged, plus anything with no service logic moved down
```

The grouping above is a proposal from file names and import edges, to be checked in step 6 against a per-domain edge count before the folders are cut.

### Allowed directions

1. `api` may import `services/<domain>/index.ts` and `infra` types, never `services/<domain>/<internal>`. The 4 `api -> infra` edges move behind services or are allowed explicitly for `project-scope` and `host/registry`.
2. `services/<domain>` may import `infra`, `services/shared` and another domain's `index.ts`. No domain imports a domain that imports it (no cycles between domains).
3. `infra` imports only npm packages, `node:*`, workspace packages and other `infra` files.
4. `mcp/server.ts` and `src/api/*` count as entry points on the api tier.

### Enforcement

1. Biome `noRestrictedImports` overrides per tier (Biome already runs these for `host-local`; `biome.json:76` is the model). `infra/**` forbids `**/services/**` and `**/api/**`. `services/**` forbids `**/api/**`. This is the cheapest rule and fails the existing `lint` script. Open item: confirm that Biome's rule also matches `import()`, because the known infra violation is a dynamic import (step 2 checks this; if it does not, step 2 also adds the check below).
2. A cycle and domain-boundary check outside Biome: `dependency-cruiser` (a new dev dependency) or a short script in `scripts/` run by the existing `lint` command. Biome cannot express "no cycles". Knip (already configured in `knip.json`) reports unused exports, not cycles.
3. Per-domain folders use `index.ts` as the only importable file from other domains, enforced by a Biome pattern per domain.
4. The review criteria CODE-2, CODE-11 and CODE-17 stay as the human-readable rule but point to the lint rule as the enforcer.
5. The web boundary is already enforced: `apps/web/tests/hub-boundary.test.ts` scans for a value import from the hub. The only import is `import type { AppRouter } from "@band-app/server"` in `apps/web/src/lib/trpc-client.ts:1`. Nothing to add.

### Docs layout

`CLAUDE.md` keeps Terms, the testing rules summary, commands, and one line per architecture topic linking to `docs/architecture/<topic>.md`. Target: about 25 KB.

## 5. Open questions

1. Is a 25 KB `CLAUDE.md` with linked `docs/architecture/` files acceptable, given that agents then read a topic file only when they open that area? The alternative is to keep `CLAUDE.md` whole and split it into path-scoped files (for example `apps/hub/CLAUDE.md`).
2. Should the Biome rule or `dependency-cruiser` be the enforcer? Biome adds no dependency but cannot detect cycles. `dependency-cruiser` handles both and adds one dev dependency.
3. In the web app, which direction do you want: `components/` depending on `dashboard/` (33 files today, because `dashboard/` holds the adapter and context) or the reverse? Today's direction is the opposite of what the names suggest.
4. Do you want the 8-domain grouping in section 3, or a coarser one (for example only `projects/` and `context/` first, since they are the biggest)? The cost of each PR in step 7 scales with the number of domains.
5. `apps/web` type-checks against `@band-app/server`'s `types: src/index.ts`, which reaches the whole hub source (53,909 lines) through `AppRouter`. A generated `.d.ts` would stop that. Is the web type-check time a pain point worth a step? I did not measure it.
6. Should module singletons (`export const xService = new XService()`, 60 files) move to a composition root? It would remove the import-time coupling but touches almost every test. I left it out of the plan and would want a separate decision.
