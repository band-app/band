# Architecture: extensions

An admin installs an editor extension as a folder in `<BAND_HOME>/extensions/<id>/` (guide: `docs/extensions.md`). The extension is web files. Its UI runs only in `<iframe sandbox="allow-scripts">` with a `null` origin, so it holds no Band token, cookie or storage, and it runs no code on the hub or a worker. The one exception is `contributes.mod`: a client mod runs unsandboxed in the page with the device token, and the admin's install is the only gate (see the Mods section of `docs/extensions.md`).

- Manifest and registry. `band-extension.json` is validated by `extensionManifestSchema` (`packages/plugin-api/src/extension-manifest.ts`, strict: an unknown key is an error; `contributes.fileEditors` has id, label, selector globs, default, entry, binary and tools). `services/extension-service.ts` reads the folder at first use and on `extensions.reload`, skips a manifest that fails (logged, and listed in `errors` with the folder and reason), and requires the folder name to equal the id. It is on the machine-access exempt list in `biome.json` because the folder is hub state. `extensions.list` (any device token) and `extensions.reload` (admin) are left out of the MCP endpoint, and the relay lists neither. CLI: `band extensions list | reload | install | remove`.
- Install from a release. `extensions.install { url, sha256? }` and `extensions.remove { id }` (admin, in `NEVER_FOR_AGENTS`, left out of the MCP endpoint) back `band extensions install <url | file.tar.gz> [--sha256]`. A URL is https (or http on loopback), 200 MB at most, 2 minute timeout, and the checksum is the given `sha256` or `<url>.sha256` when that exists. A local file goes up as the raw body of `POST /api/extensions/install[?sha256=]` (admin token; a request with an agent's chat, worktree or terminal header gets 403). `ExtensionService.installArchive` reads the archive in memory with `@band-app/shared/tar-extract` (refuses links, absolute and `..` paths, more than one top-level folder, `._*` files are skipped, 500 MB expanded), validates the manifest with the existing schema, requires folder name = `id`, writes to `.install-<tag>` under the extensions folder and renames over `<id>` (the old folder is kept as `.old-<tag>` until the swap works), then reloads. The scan skips folders that start with a dot. Private release assets: `gh release download`, then install the file. Tests: `apps/hub/tests/extensions-install.test.ts` (Express stub, `helpers/make-tar.ts`), `extensions_install_*` in `apps/cli/tests/integration.rs`.
- Serving. `GET /ext/<id>/<path>` (`api/extensions/handler.ts`) is answered at the top of `handleRequest`, before CORS and the device-token check, because a `null` origin carries no credentials. Static files only, `Access-Control-Allow-Origin: *` on every answer including preflight, `application/wasm`, the `.br` or `.gz` copy when accepted, 404 for `..`, an encoded slash, a symlink out, a folder and an unknown id, and no cookie read or set.
- Saving. `PUT /api/worktree-file/<worktreeId>/<path>` (`api/worktree-file-put.ts`, after the auth check) takes a raw body up to 50 MB (413), applies the GET route's path rules (400 for a path or symlink out of the worktree and for `.git`), requires an existing file (404 otherwise) and writes through `host.fs.writeFile`, so a worktree on a worker is written there. The desktop app saves and reads on this Mac's worker over the local direct path first (`ExtensionEditor.tsx`, see Architecture: local direct path) and falls back to this route. A request with `x-band-chat-id`, `x-band-worktree-id` or `x-band-terminal-id` gets 403, and the relay lists no such route.
- Web. `lib/extensions.ts` holds the registry (`extensions.list` through react-query), `resolveEditor` and the "Open With" choice. An editor is named `<extensionId>/<editorId>` and `builtin` is the code viewer. The order is the file's choice (the `editor` field of its `band-tab-state:<ws>` entry, synced with scope `all`), then the glob defaults (`band:extension-defaults`, synced, scope `all`), then a manifest `default`. A choice that names a removed editor falls back to the built-in viewer. The tab stays `file:<path>`. `EditorChoiceFileLeaf` in `WorktreeCenter.tsx` picks `ExtensionEditor` or the code viewer, and `OpenWithItems` is the submenu in the Explorer and tab menus.
- Protocol (`components/extensions/ExtensionEditor.tsx`): `band:hello` with one transferred `MessagePort`, then `init`, `ready`, `dirty`, `save` to `PUT` to `saved` or `saveFailed`, `requestSave`, `theme`, `reload`, and `mcp` (a request matched to its answer by id, `ExtensionEditorHandle.mcp`, with no caller yet). Unsaved edits are tracked on the page only (`setExtensionDirty`), never synced, and feed the tab's dirty dot and the close confirm. After a save or a file-watch event the tab fetches the bytes and compares them with the ones it knows: no edits sends `reload`, edits show the "load theirs or keep mine" banner (same test ids as the code viewer's).
- Layout. An iframe reloads when its element is removed, so an extension tab sets its panel renderer to `always` (`PanelApi.setRenderer`) and stays attached while hidden, and `LayoutView` moves a panel element between groups with `moveBefore` when the browser has it, so a tab moved to another group keeps its document. A browser without `moveBefore` reloads the frame on a move and the editor starts from disk.
- Isolation. The frame is never given `allow-same-origin`. `/ext/` has no network CSP in v1, so a frame can still make requests.
- Tests: `apps/hub/tests/extensions.test.ts` (real hub), `extensions-remote.test.ts` (real `band-worker`), `apps/web/e2e/extension-editor.spec.ts` and `extension-editor-mobile.spec.ts` with the fixture `apps/web/e2e/fixtures/extensions/text-editor/`, `extensions_*` in `apps/cli/tests/integration.rs`.
- Worker services (guide: `docs/extensions.md#worker-services`). `contributes.workerServices` (`id`, `entry` .mjs, `requires`, `capability`) makes an extension run a process on each eligible worker. `ExtensionService.installArchive` keeps the `.tar.gz` and its sha256 in `<BAND_HOME>/extensions/.archives/`. `services/extension-worker-service.ts` sends `extensions.sync { items: [{id, version, sha256}] }` (link `packages/link/src/extensions.ts`) on worker connect, install, update, removal and `hosts.setTrust`, answers the worker's `extensions.fetch` (archive over a payload channel), and returns `extensionServices` per worker in `hosts.list`. A restricted worker gets an empty set and shows `not-eligible: restricted`, and the hub's own machine runs none. The worker (`apps/worker/src/extensions.ts`, `ExtensionHost`) verifies the sha256, unpacks with `@band-app/shared/tar-extract` under `<state dir>/extensions/<id>/<version>/`, drops other versions, and starts one process per service whose `requires` hold. The spawn (`serviceSpawnSpec`) sets `ELECTRON_RUN_AS_NODE=1` itself under Electron and passes an env allowlist with no `BAND_*` or `GIT_CONFIG_*`. NDJSON on stdio, stream frames on fd 3 (`packages/extension-worker-sdk`, `defineWorkerService`). Restart after 1, 2, 4 s, `failed` on the third exit within 5 minutes, killed on lease fence (restarted by the next call after a renewal), shutdown, removal, update and trust drop. `plugin.call` and `plugin.stream` route to a service by capability, and a bundled plugin of the same id wins. `extensions.callService` (admin, left out of MCP and the relay) calls a service for a worktree. A stream is `/api/plugins/<capability>/worktrees/<id>/stream`: any device token, input from the start, never an agent. The hub remembers the set each worker acknowledged and resends `extensions.sync` on every connect and lease renewal until it matches (`ExtensionWorkerService.onRenewed`). The worker starts or restarts nothing while its lease is not valid (`LeaseGuard.isFenced`, `ExtensionHost.resume` on renewal). Tests: `apps/worker/tests/extensions.test.ts` (real worker, fence, crash loop, spawn env), `apps/hub/tests/extension-worker-services.test.ts` (real hub, two real workers, fixture `fixtures/extensions/echo-service`). Not tested: a run inside the desktop bundle, because tests never start the installed Band.app. Not done yet: persisting served worktrees across a service restart.
- Panels and tools (guide: `docs/extensions.md#panels`). `contributes.panels` (`id`, `label`, `icon`, `entry`, `capability`) and `contributes.tools` (`name`, `description`, `inputSchema`, `service`, `method`, `agent`) in `extension-manifest.ts`. The schema refuses a panel whose `capability` no service reports and a tool whose `service` is no service id. `workers.list` adds the capabilities of running extension services to each row's `capabilities` (the hello's list is fixed at connect), and the center "+" menu offers a panel when the worktree's worker is online and lists its `capability` (`useExtensionPanels`, `use-plugin-slot.ts`). The tab is kind `plugin` with id `ext:<extension id>:<panel id>` (owner id `ext:<extension id>` in `pluginPanelTabId`), renderer `always`, stored in `band:center-tabs`. `ExtensionPanel.tsx` runs the page in `<iframe sandbox="allow-scripts">` and speaks the panel protocol over a `MessageChannel` (`band:hello`, then `init`, `stream.*`, `call`, `control`, `visible`, `layout`, `theme`; `useThemeUpdates` in `ExtensionEditor.tsx` sends `theme` to editors and panels alike). Streams go to `/api/extensions/<extension id>/worktrees/<worktree id>/stream?panel=&name=&params=` (`api/extensions/stream-handler.ts`, bridged by `bridgePluginStream`: text input reaches the service from the start, a `control` frame is accepted and ignored, binary input is dropped; the panel has no Take control button and the page gets `control {enabled: true}` when its first stream opens). The hub finds the service from the panel's capability, so a panel reaches only its own extension's services. `extensions.panelCall` (any device token, left out of MCP and the relay) is the panel's `call`. Tools join the built-in `band` MCP server as `<extension id>_<name>` (`api/mcp-proxy/extension-tools.ts`, schema advertised through `advertiseToolSchemas`), call `pluginHost.callWorker` for the calling chat's worktree only, and answer an error naming the worker when it lacks the service. `agent: false` tools are left out. No tab is needed. Agents never open a stream: the relay lists neither the route nor `extensions.panelCall`. A panel's stream tries the worker's direct listener first in the desktop app (see Architecture: local direct path) and the service's stream params carry `profile: "direct" | "hub"`, set by Band after the page's params. A tool's service may return `{ content: [...] }` with text and image blocks, which the MCP result passes on. Tests: `apps/hub/tests/extension-panels-tools.test.ts` (real hub, two real workers, ACP stub `mcpCall`), the `extension-panel-*` probes in `remote-relay.test.ts`, `apps/web/e2e/extension-panel.spec.ts`. Not done yet: mobile panels.
- Official catalog (`services/extension-catalog-service.ts`, guide: `docs/extensions.md#official-extensions`). The hub fetches one `index.json` (`BAND_EXTENSION_CATALOG_URL`, read on every fetch, default the `catalog` release of `band-app/band-extensions`) at startup and every 24 h, validates each entry with zod (`id, name, description, version, url, sha256, minBand, worker, requires`, bad entries skipped) and keeps it in memory; a failure is logged once per outage. `extensions.catalog` (any device token) returns the entries with `official`, `installed`, `updateAvailable` and `compatible` (`minBand` against `HUB_VERSION`). `extensions.refreshCatalog` and `extensions.installOfficial { id }` are admin only and in `NEVER_FOR_AGENTS` through the `extensions.` prefix. `installOfficial` installs the entry's url with its sha256 through `installArchive` and records `source: "official"`; an update is the same call. `installArchive` writes `<extensions>/.installs/<id>.json` (source, sha256, version), `extensions.list` returns it as `sources` and marks an extension official when the record says so or its sha256 equals the catalog's. CLI: `band extensions catalog | install --official <id>`. Tests: `apps/hub/tests/extensions-catalog.test.ts`, the `extensions-install-official` probe in `remote-relay.test.ts`, `apps/web/e2e/settings-extensions-catalog.spec.ts`, `extensions_catalog_*` in `apps/cli/tests/integration.rs`. Not done yet: auto-update, and worker parts of extensions.
- Language servers (guide: `docs/extensions.md#language-servers`). Band bundles none: the hub and worker builds hold no typescript-language-server. `contributes.languageServers` (`id`, `languages`, `files`, `command`, `args`, `rootMarkers`, `requires`) in `extension-manifest.ts`. The hub syncs an extension that has only language servers to eligible workers like a worker service (`desiredFor`). `ExtensionHost.languageServers()` (`apps/worker/src/extensions.ts`) builds the list from the unpacked folders and `LocalHost` reads it through its `languageServers` option on every connection (`packages/host-local/src/lsp/lsp-manager.ts`: a `.js`/`.mjs`/`.cjs` command runs under the worker's node, else a binary on the PATH; `rootMarkers` gate the start; an unmet `requires` is "needs <binary>"). The `lang` of `/lsp` is `<extension id>/<server id>`. `workers.list` returns `languageServers` per worker (none for a restricted worker or the hub's own machine), and `useLanguageServerFor` (`apps/web/src/lib/language-servers.ts`) picks the server for a file by glob. Tests: `apps/hub/tests/lsp-extension.test.ts`, `lsp-reconnect.test.ts` and `direct-path.test.ts` (a stand-in `typescript-lsp` extension from `helpers/lsp-extension.ts`, the real typescript-language-server as a hub dev dependency), `apps/web/e2e/diff-lsp-navigation.spec.ts`, the host contract suite (a stub server). Not done yet: `initializationOptions`, language servers on the hub's own machine, native servers.
- Settings > Extensions is `ExtensionsSettings.tsx` (list with load errors, install by URL or upload, remove, reload, default editor per selector glob in `band:extension-defaults`; read-only for non-admins). Tests: `apps/web/e2e/settings-extensions.spec.ts`.
- Agent access (`docs/extensions.md`, Agent access). `services/editor-registry-service.ts` keeps the editor tabs each window registered (`editors.register | unregister`, keyed by the client id of `activity-reporter.ts`, dropped when `ClientActivityService` expires the client), the latest selection per worktree, and the calls in flight. `api/editors/router.ts` adds `result`, `setSelection` and `selection`. All `editors.*` are device-token only: `NEVER_FOR_AGENTS` in `relay-scope.ts` and the MCP endpoint's skip list refuse them. `api/mcp-proxy/editor-tools.ts` adds `band_editor_list | open | selection` and each editor's `tools.json` tools (`<extension>_<tool>` with a required `file`, `"agent": false` left out) to the built-in `band` server, for the chat's own worktree only. A call goes out as an `editor-call` status event addressed to one client (`StatusEvent.editorRequest`), the window that most recently had focus (`ClientActivityService.clientsByFocus`), and comes back through `editors.result`. `band_editor_open` sends `editor-open` and waits for the tab to register. Agents never save. Protocol additions: `init.layout` and `layout` (`compact` under 1024 px or on `/embed/editor`), and `selection` from the editor. The composer shows `EditorSelectionChip` and appends the `Selected in …` block (`lib/editor-selection.ts`). `/embed/editor` (`routes/embed.editor.tsx`, rendered without the shell by `RootLayout`) is the iOS web view's page. Tests: `apps/hub/tests/editor-agent-access.test.ts` (a `FakeWindow` on the status stream, the ACP stub's `mcpCall`), the `editors-*` probes in `remote-relay.test.ts`, `apps/web/e2e/extension-editor-agent.spec.ts`, `extension-editor-embed.spec.ts`, and the S6 case in `extension-editor-mobile.spec.ts`.
- Not done yet: install from a `.bandext` zip, per-extension origins, new files, and opening a tab for `band_editor_open` in the phone-width layout.
- Client mods (guide: `docs/extensions.md#mods`). `contributes.mod` (`css` as a file or a list, `module`, `window`) runs unsandboxed in the page with the device token. `apps/web/src/lib/mods.tsx` (`ModsLoader`) adds the CSS links and imports the module, which is called with the `band` host object (`packages/plugin-api/src/mod-api.ts`). `dashboard/mods/registry.tsx` holds the overrides: `<Overridable name render>` wraps `sidebar`, `sidebar.repoGroup`, `sidebar.worktreeCard` and `worktree.header` (center layout only), a throwing override renders the stock element and is listed in Settings > Extensions, and `sidebar.items` transforms each repo's worktrees. Safe mode: `BAND_MODS=off` (`extensions.list` returns `modsOff`), the "Turn off mods" switch (a shadow root on a fixed body child, `localStorage` `band:mods-off`) and `?mods=off`. Desktop: `services/mod-window.ts` reads `<home>/.band/extensions/*/band-extension.json` at window creation (`material` as an Electron vibrancy name or `none`, `titleBarStyle`, `toolbar`, `trafficLightPosition`). `apps/desktop/native/band-native.mm` (N-API, built by `native/build.mjs` for arm64 and x64 on macOS, shipped as `Resources/native/band-native.node` through `extraResources` and signed in `after-pack.mjs` (an `asarUnpack` pattern made electron-builder reject the symlinked workspace packages), optional at runtime, `BAND_FORCE_NATIVE_LOAD_FAIL=1` forces it off) gives an empty `NSToolbar` (large corner radius, `window.toolbar`) and SF Symbol rendering. `services/system-colors.ts` injects `--mac-*` CSS variables with `insertCSS` (appearance and accent changes update them, and are read again 120 and 400 ms later because AppKit's appearance settles after the event) and `--mac-symbols: 1` when the addon loaded; `services/symbols.ts` serves `band-symbol://<name>?pt=&w=&s=` as PNG (CSP `img-src` allows the scheme). Band no longer puts Liquid Glass behind the window: the spike showed a native glass view above the page blurs the labels, one synced from the page over IPC trails the DOM by 1.5 to 2.5 frames, and a window-level one with the page cutting holes needs a non-opaque window and a view that returns nil from `hitTest:` or it takes every click. The look is flat CSS over the window's `sidebar` vibrancy. Tests: `apps/hub/tests/extensions.test.ts` (manifest), `apps/desktop/tests/mod-window.test.ts` and `mod-native-services.test.ts`, and the packaged-app job, which builds the addon into the bundle. Not done yet: a Playwright spec for mods (regions, the sidebar transform, safe mode).
